# 五、六阶外援：赤刃明霄陈、望

本分支基于上游 0.1.4、`master` 的 `9f93096efaf4d1e671c76b8ca3efc4692b02d15b`。固定干员、经济数值和既有战斗接口沿用原项目，增加两名外援的招募、精锐化、调配与作战流程。

## 选择与调配

从大厅、房间或战前简报打开「干员调配」，五阶、六阶各有两个外援位置，默认留空。目前仅能选择赤刃明霄陈与望；同一玩家不能在不同位置或不同阶重复选择同一干员，队友之间可以重复选择。

选中后可在详情切换三个技能及精锐模组，默认三技能和唯一进阶模组，也可以不装备模组。旧预设没有 `diy` 字段时按空外援处理；外援选择与技能设置一起导出、保存到浏览器、同步到服务器会话与席位。战前简报仍可调整，离开该阶段后本局锁定；沿用原项目规则，之后的编辑保存给下一局。

| 状态 | 等级 | 技能等级 | 模组 |
|---|---|---|---|
| 五、六阶初始 | 精二一级 | 四级 | 无 |
| 五阶精锐 | 精二六十级 | 七级 | 一级进阶模组或不装备 |
| 六阶精锐 | 精二六十级 | 七级 | 三级进阶模组或不装备 |

陈使用「记忆残页」AFT-X，望使用「兽形棋盒」TRP-X。两阶共用战斗逻辑，从各自数据读取属性、技能黑板和模组天赋。按历史角色势力数据及本次确认，两人仅有【炎】盟约，没有额外卫戍特质。

另提供[固定 99 资金的干员测试版](DIY-TEST.md)，可独立一键启动，默认使用 3001 端口。

## 卡池与信标

**[ASSUMED] 外援独立卡池是本次开发采用的暂定规则，原版玩家之间是否共享外援库存尚未确认。** 固定干员继续使用跨玩家共享卡池。每名玩家所选外援单独计数，五阶 8 份、六阶 5 份，初始占 1 份、精锐占 3 份，沿用项目的数量模型。抽取把该玩家剩余的固定干员与所选外援合并，使用现有按剩余份数加权算法。

商店、合成奖励、盟约招募和其他随机获得入口仅能给该玩家已选择的外援。购买、晋升和直接获得精锐需要足够个人份数；合成、出售、离场及整备区溢出按持有份数扣除或归还。不同玩家的同名同阶外援库存互不影响。库存耗尽后外援不会继续出现在随机抽取中。

普通与精锐信标均不能配发给初始或精锐外援。服务器提前拒绝该操作，信标、干员、资金及装备均保留，不安排延迟赠送或下回合返还。限制依据为[活动结束前的客户端 `activity_table.json`](https://github.com/Kengxxiao/ArknightsGameData/blob/86da4cfa3a4b958c3615fccf5afbc10b5c7f1bfb/zh_CN/gamedata/excel/activity_table.json)中的「无法装备给自编干员」。普通干员的信标行为继续沿用原实现。

## 陈的战斗行为与双模机械臂

- 一技能：攻击加成、二连击和持续至技能结束的沉默。
- 二技能：间隔斩击、击杀转移与追加次数，斩击时不可攻击、阻挡或获得技力，并免疫伤害及晕眩、冻结；结束时尝试移动到仍存活目标的合法位置，否则回原位置，之后保留六秒增益。
- 三技能：扩大范围、多目标三连击，以及独立运动的剑气。剑气用当前生命比例与攻击力下限取较大值，撞墙后顺时针转向（上→右→下→左），每次转向前同一敌人只受一次剑气伤害。专项测试覆盖两阶、两形态、四方向和连续碰墙。
- 天赋与模组：攻击的弱点伤害判定、攻击与攻速加成、未受伤后的确定性随机治疗及下一次闪避、无阻挡时的模组攻速。

陈的攻击与双模机械臂复用同一个 `weaknessRetype` 函数：比较物理与法术理论减伤，改变类型后只结算一次伤害。两个弱点来源不会增加伤害次数或重复乘算。装备的攻击力加成仍按原装备规则正常叠加。

专项回归覆盖五、六阶 × 初始/精锐 × 三个技能 × 普通机械臂/精锐机械臂/两者同时佩戴 × 三种目标抗性，共 **108 组**；验证击中次数、数值、类型和战斗不变量。另验证真实及元素伤害保持原类型。三技能剑气不受「攻击」天赋重设，但机械臂沿用原项目对所造成物理/法术伤害的类型转换规则；生命比例和最低伤害公式不变。浏览器与服务器也比较装备后的战斗摘要。

## 望的棋子

休整期部署望后，项目现有召唤物手牌机制提供棋子卡，可将棋子摆到合法地块。模组可提供七个占位棋子位置，但开场库存只有六枚；第七枚等待技能补充库存后再自动部署。占位棋子绑定具体召唤者；跟子是效果，既不占棋盘单位位置，也不占部署人数。相邻同属棋子或跟子激活连线，二技能激活过的轴向不会因相邻棋子消失而取消；连续直线提供伤害与法抗忽略，至多三层。

一技能触发停顿与独立持续伤害，按触发时望本体的攻击力和棋子层数保存数值；二技能沿激活轴攻击并施加独立减速；三技能扩大被动触发范围，主动增加棋子库存，溢出生成跟子，范围内再次部署最多额外生成三个跟子并扣除实际生成数量的弹药，结束返还剩余弹药为棋子。跟子优先敌人格，其次按地块类型及上、右、下、左顺序生成；在其位置部署单位会清除它。

作战期继续使用项目自动操作：已摆过的占位棋子触发消失后，等待自身再部署时间、库存、费用与三秒操作冷却，再尝试回到原格。三技能范围外仍遵守通常部署限制。望离场时清理附属棋子和跟子，多名玩家的望不会共用库存、弹药、连线或召唤物归属。跟子随战斗快照同步，可在队友查看、断线接管及联防中显示。

## 数据生成与素材

外援数值固定使用活动结束前的历史提交 `86da4cfa3a4b958c3615fccf5afbc10b5c7f1bfb`，从活动、角色、技能、范围、模组与战斗模组表生成。生成器复用 `tools/build-data.mjs` 的角色和召唤物解析，不手改生成 JSON。

```sh
node tools/build-data.mjs                   # 普通构建同时接入外援
node tools/build-diy.mjs                    # 只重建外援及盟约成员
node tools/build-diy.mjs --offline          # 使用 .cache/diy/<提交号>/ 历史缓存
node tools/fetch-assets.mjs                 # 按清单下载新增素材
```

`--no-research` 保持原有纯客户端数据构建，不加入额外外援目录。`build-data --offline` 需要普通缓存和历史外援缓存。已验证普通完整构建的全部 JSON 与提交数据逐字节相同。

游戏素材、缓存、截图、日志和本机穿透配置均不提交。当前配置的素材源未提供 `token_10064_wang_stone1` 的独立 Spine，棋子使用项目既有图标回退；两名干员本体的 Spine 正常加载，跟子以棋子标记绘制。

## 与原版的边界及后续核验

保留原项目自动战斗、移动再部署与联防继承规则。剑气通过现有固定步长投射物接口前进，地块碰撞按项目棋盘几何判定，存续上限暂与技能持续时间一致；复杂拐角的轨迹和存续时间仍需原版录像核验。棋子的再次部署采用原格自动重试，没有新增作战时手动操作入口。联防从阵容重新建立棋子状态，不迁移上一场临时跟子或活动中的技能，沿用现有召唤物继承标准。

后续核验按 `to-issues` 的完整玩法切片整理为本地清单，尚未发布 GitHub Issue：

1. **外援库存原版核验（HITL）**：取得同名同阶外援多人招募的实录，确认数量与共享规则；若结论不同，同时更新抽取、扣还、界面说明和多人测试。
2. **剑气轨迹与棋子自动部署实录对照（HITL）**：使用拐角、狭窄地形和联防实录检查轨迹/存续与棋子选择；任何修正同时覆盖单人、多人和浏览器一致性测试。
3. **棋子独立动画（AFK）**：素材源具备模型后更新下载清单，验证桌面、手机、队友查看与跟子覆盖显示。
